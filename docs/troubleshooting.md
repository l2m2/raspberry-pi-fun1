## 1. Mac 提示"此电脑不能读取你连接的磁盘"，SD 卡上没有系统

**日期**：2026-10-10

**现象**：SD 卡插到 Mac 上弹出"此电脑不能读取你连接的磁盘"。

**排查**：`diskutil list external physical` 显示卡（16GB）上**没有任何分区**。正常烧好的卡应有 `bootfs`（FAT，Mac 可读）和 `rootfs`（ext4，Mac 不可读）两个分区。

**原因**：之前的烧录没有成功，或者卡被清空了。

**解决**：在弹窗里点"忽略"（不要点"初始化"），然后用 Raspberry Pi Imager 重新烧录。在"编辑设置"里预先配置好用户名和密码、WiFi（国家选 CN）、开启 SSH。

> 注意：烧好的卡插到 Mac 上**也会**弹"不能读取"，那是 `rootfs` 分区导致的，属于正常现象。

## 2. 烧录后 Mac 看不到 SD 卡

**现象**：Imager 烧录完成后，反复插拔读卡器，`diskutil` 都看不到卡。

**排查**：
- Imager 写完会自动弹出卡，所以要拔掉重插。
- `ioreg -p IOUSB` 能看到读卡器（Generic Mass Storage Device），但读卡器里没有检测到卡。
- 用 `log show --predicate 'process == "diskarbitrationd"'` 查日志，烧录后卡曾以 `disk2s1`、`disk2s2` 两个分区出现过。这说明**烧录本身成功了**，只是挂载 `bootfs` 失败，之后卡就断开了。

**原因**：读卡器或卡接触不良。

**解决**：跳过在 Mac 上检查，直接把卡插回树莓派上电验证，结果启动成功。

## 3. 开机后绿灯"有规律地闪"，网络里扫不到树莓派

**现象**：上电后绿色 ACT 灯持续闪烁，局域网里扫不到 SSH。

**原因**：这不是报错。Pi 3B+ 的绿灯是 SD 卡读写指示灯，**第一次开机**会自动扩容分区并重启，期间会长时间闪烁。启动完成后绿灯熄灭，只剩红色电源灯常亮。

**解决**：等绿灯安静下来再扫描，就找到了。

**怎么区分正常启动和报错**：报错是**一组固定次数的闪烁，一直循环重复**。Pi 3B+ 的闪码含义：

| 每组闪几下 | 含义 |
|---|---|
| 3 | 找不到 start.elf |
| 4 | start.elf 无法启动（文件损坏） |
| 7 | 找不到 kernel 内核 |
| 8 | 内存故障 |

## 4. 用主机名 `raspberrypi` 连不上

**现象**：`raspberrypi` 能解析到 `28.0.0.78`，但 SSH 一连接就被断开（`Connection closed`）。

**原因**：Mac 上运行着代理软件（TUN 模式，`utun4` 的地址是 `28.0.0.1`）。它用 fake-ip 方式把这个主机名解析成了一个假地址，并不是真正的树莓派。另外，这台树莓派的主机名其实是 `l2m2rp1`。

**解决**：不用主机名，直接扫描局域网找 IP：

```bash
# 找开着 22 端口的设备
for i in $(seq 2 254); do (nc -z -G1 -w1 192.168.1.$i 22 2>/dev/null && echo "192.168.1.$i") & done; wait
# 或者按树莓派的 MAC 前缀找
arp -a | grep -iE 'b8:27:eb|dc:a6:32|e4:5f:01|d8:3a:dd|2c:cf:67|88:a2:9e'
```

找到 IP 后填到 `.env` 的 `PI_HOST`。

## 5. 电源供电不足，CPU 被降频（已解决）

**现象**：`vcgencmd get_throttled` 返回 `0x50005`。

**含义**：

| 位 | 含义 |
|---|---|
| bit 0 | 当前处于低电压 |
| bit 2 | 当前正在降频 |
| bit 16 | 开机以来出现过低电压 |
| bit 18 | 开机以来出现过降频 |

**影响**：性能下降，严重时会损坏 SD 卡数据。以后接上舵机会更严重。

**解决方案**（待执行）：
- 换 5V 2.5A 以上的电源，最好是官方电源。
- 换短而粗的 USB 线。
- 舵机必须单独供电，和树莓派只共地。
- 换好后重新检查，`get_throttled` 应返回 `0x0`。重启后高位的历史记录才会清零。

**尝试记录**：

| 日期 | 供电方式 | 结果 |
|---|---|---|
| 2026-10-10 | 插线板上的 USB 口 + 原线 | `0x50005`，低电压并降频 |
| 2026-10-10 | 手机充电头 + 原线 | 仍为 `0x50005`，CPU 只跑 600MHz（满速 1.4GHz）。说明线才是瓶颈 |
| 2026-10-20 | Mac 转接头的 USB-A 口 + 绿联 0.25m Micro-USB 线（2A） | 刚开机时 `0x50005`、600MHz，空闲时偶尔恢复到 `0x50000`、1.4GHz，一有负载又低电压。这个口一般只能输出 0.5～1.5A，本来就带不动 Pi，所以这次不能说明短线有没有用 |
| 2026-10-20 | 手机充电头 + 绿联 0.25m Micro-USB 线（2A） | 空闲和 4 核满载 30 秒时都是 `0x0`，满载时 1.4GHz，没有低电压告警。**问题解决** |

**结论**：瓶颈是原来那根 Micro-USB 线。换成短线后，手机充电头就够用了。

**附：满载时出现 `0x80008`**：温度到 60°C 后，`get_throttled` 变成 `0x80008`，频率从 1.4GHz 降到 1.2GHz。这是 bit 3 / bit 19（触发软温度限制），是 Pi 3B+ 的正常保护，和供电无关。长时间高负载可以加散热片。

## 6. SD 卡插到 Mac 上，`bootfs` 挂载失败（I/O 错误）

**日期**：2026-10-20

**现象**：树莓派直接拔电后，把卡插到 Mac 上。`diskutil list` 能看到 `disk2s1`（bootfs），但 `diskutil mount` 报 `failed to mount`。用 `readOnly` 挂载也失败，系统日志里是 FSKit `NSPOSIXErrorDomain Code=5`（I/O 错误）。在这之前，读卡器还整个掉线过一次。

**排查**：`diskutil verifyVolume disk2s1`（只读的 `fsck_msdos -n`）检查通过，只报了 FSInfo 空闲空间计数不对。这是没正常关机留下的，不影响使用。说明卡上的数据是好的。

**解决**：做完 verify 后再执行 `diskutil mount disk2s1` 就挂上了。挂载失败多半是读卡器接触不良（同第 2 条），加上 macOS FSKit 偶尔出错。读卡器还是不稳定，可以考虑换一个。
